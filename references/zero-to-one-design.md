# Zero-to-One Validation Design

## Identify the Load-Bearing Claim

Ask which single claim, if false, would make the proposed project no longer worth pursuing in its current form. Express it as a relation between an intervention or condition and an observable consequence.

Examples:

- A material can be produced with two meaningfully different target morphologies.
- A known photoresponsive electrode can lower charging voltage in the intended battery configuration.
- Extracted platform data contain the variables needed for the planned analysis.
- A treatment produces the required effect in vitro before animal or clinical work is considered.

Do not automatically choose the first chronological step. The first operation may be technically difficult but irrelevant to whether the central idea works.

## Use Backward Design

Start with the result that would justify continued investment, then ask:

1. What observation would demonstrate that result?
2. What measurement can detect it with the least ambiguity?
3. What inputs and controls must exist for that measurement to be interpretable?
4. Which preparatory steps can be replaced by known-good components?

This often produces a shorter path than following the anticipated full study from beginning to end.

## Apply the Deletion and Substitution Tests

For each step:

- Delete it mentally.
- Ask whether the core claim can still be tested.
- If it can, defer the step.
- If it cannot, retain it.
- If a custom version is unnecessary, substitute a commercial, standard, published, or otherwise validated version.

The aim is not to prove that every component is optimal. The aim is to isolate the uncertain relation with minimal collateral uncertainty.

## Separate Gates

A project may require more than one gate:

1. **Existence gate** - can the intended entity, effect, or dataset be obtained?
2. **Functional gate** - does it perform the necessary function?
3. **Comparative gate** - is the advantage meaningful relative to a baseline?
4. **Translation gate** - does it remain useful under realistic constraints?

Use only the gates required to decide whether to proceed. For some ideas, preparation alone is insufficient because a produced material may have no useful performance. For others, the phenomenon already exists and the project can enter one-to-ten development directly.

## Define a Validation Contract

Write the contract before extensive reading or experimentation:

| Field | Question |
|---|---|
| Claim | What must be true? |
| Test unit | What exactly is being tested? |
| Comparator | Compared with what? |
| Controls | What confirms the system and measurement work? |
| Readout | What minimum observable decides the claim? |
| Threshold | What counts as enough? |
| Ambiguities | What alternative explanations remain? |
| Budget | How many iterations, how much time, and what cost are acceptable? |
| Decision | What happens after each outcome? |

## Prefer Milestones Over Exhaustive Plans

The zero-to-one milestone should be:

- decisive enough to change the project decision;
- cheap and fast relative to the full study;
- interpretable with available controls;
- narrow enough that failure can be diagnosed;
- expandable into a publishable program if successful.

Reserve systematic optimization, broad characterization, mechanism, performance mapping, figure design, and manuscript construction for one-to-ten development.
